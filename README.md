# Safepets storefront

Nuxt 3 storefront for **[safepets.ru](https://safepets.ru)** — a shop for personalised pet gear:
address tags (адресники), collars, leashes and other accessories. The product page is a design
constructor: the buyer picks a base artwork, colour and font, types a name or a phone number into the
defined text lines, sees a live SVG preview, and only then puts the item into the cart.

The backend is a Laravel GraphQL API — [maylogic/sbe1](https://github.com/maylogic/sbe1).
This repository is the frontend only: SSR pages, the constructor, the cart, checkout and the
server-side rendering of print-ready artwork.

## Stack

| Layer | Technology |
|-------|------------|
| Framework | Nuxt 3 (SSR, Nitro), Vue 3, TypeScript |
| GraphQL client | [`@urql/vue`](https://formidable.com/open-source/urql/docs/) — `cacheExchange` + `ssrExchange` + `fetchExchange` |
| Typed operations | GraphQL Codegen (`@graphql-codegen/typescript-vue-urql`) → `gql/`, committed |
| State | Pinia — `stores/auth.ts`, `stores/cart.ts`, `stores/modal.ts` |
| UI | Nuxt UI 2, Tailwind (typography plugin), `@nuxt/icon` (lucide + heroicons), swiper |
| Forms | plain Vue components with `yup` schemas (`components/Form`, `components/Checkout`) |
| Server rendering | `svgdom` + `@svgdotjs/svg.js` (headless DOM), `skia-canvas` (text metrics), `sharp` (raster) |
| Runtime | Node 22.12 (`.nvmrc`), npm |

## The design pipeline

The artwork lives in the backend as data: a `Design` references a base SVG plus the allowed colours
and fonts, and a product carries `ProductLineDefinition` rows (label, `max_length`, sort) that say
where text may go.

Rendering that data into a personalised image happens twice, both times through the same layout code:

- **in the browser** — `utils/svg.ts` clones the base into the page's SVG and places the text,
  measuring with a hidden `<canvas>` (`utils/canvas.ts`);
- **on the server** — `server/utils/svg.server.ts` does the same on an `svgdom` document,
  measuring with `skia-canvas` (`server/utils/canvas.server.ts`), and `sharp` rasterises the result.

`utils/text.ts::computeTextLayout` is the single source of truth for line breaking, font size fitting
and baseline placement, and it receives the canvas context as an argument. That is how the cart preview,
the font picker preview and the print file stay identical to what the customer saw.

## Server routes (Nitro)

| Route | Purpose |
|-------|---------|
| `GET /api/healthcheck` | `{ status: 'ok', timestamp }` — for uptime checks |
| `GET /api/cart-item-preview/:id/:updatedAtHash` | PNG preview of a cart item's personalised artwork |
| `GET /api/font-preview/:id/:updatedAtHash` | rendered specimen of a font |
| `GET /api/order-item-pdf/:id` | print-ready artwork of an order item (`?many&page` for sheets) |
| `GET /api/items-feed.xml` | Google Merchant product feed |
| `GET /api/vk-items-feed.xml` | the same feed in the shape VK expects |
| `GET /api/dt-texts-data/:filename` | extracts template/line data from the legacy designer JSON (`data/source/*.json`) |

`updatedAtHash` in the preview URLs is a cache-busting segment, so a CDN can keep serving immutable
images for unchanged personalisations.

## GraphQL wiring

`system/createGraphqlClient.ts` builds the urql client:

- URL from `NUXT_PUBLIC_GRAPHQL_URL` (`utils/env.ts` reads the runtime config, or `process.env` while
  prerendering);
- `credentials: 'include'` plus an explicit `Cookie` header on the server, so the Laravel session
  (`laravel_session`) of an anonymous cart survives SSR;
- optional `XDEBUG_SESSION_START` passthrough, driven by the `XDEBUG_SESSION` cookie.

`plugins/urql.ts` plugs in the `ssrExchange` and ships the server-side query cache to the client in
`nuxt.payload.__GRAPHQL_DATA__`, so queries run during SSR are not repeated on hydration.

## Requirements

- Node 22.12 (`nvm use` reads `.nvmrc`)
- npm
- a reachable GraphQL backend (Laravel project `sbe1`) and a storage host for fonts and images —
  the build does not need them, but pages render empty without them

Native dependencies (`canvas`, `skia-canvas`, `sharp`) ship prebuilt binaries for common platforms.
On a machine without a build toolchain use the bundled helper, which mounts the repo into the official
Node image:

```bash
./dockernpm.sh npm ci
./dockernpm.sh npm run build
```

## Setup

```bash
nvm use                 # or install Node 22.12
npm ci
cp .env.example .env    # then edit the values below
npm run dev             # http://localhost:3000
```

`.env.example` uses `$PROTO` / `$DOMAIN` placeholders — replace them with real values, e.g.
`NUXT_PUBLIC_GRAPHQL_URL=https://safepets.ru/api/graphql`.

| Variable | Meaning |
|----------|---------|
| `NUXT_PUBLIC_GRAPHQL_URL` | GraphQL endpoint of the Laravel backend |
| `NUXT_PUBLIC_STORAGE_URL` | base URL of the storage that serves fonts, photos and base SVGs |
| `NUXT_PUBLIC_CANVAS_SIZE` | size of the measuring canvas, px — too small breaks text width |
| `NUXT_PUBLIC_CANVAS_DPI` | canvas DPI used when measuring |
| `NUXT_PUBLIC_SITE_NAME`, `_SITE_DESCRIPTION`, `_SITE_DOMAIN` | SEO title, description and canonical host |
| `NUXT_PUBLIC_DEV_TERMINAL`, `_DEV_TERMINAL_PASS`, `_PROD_TERMINAL`, `_PROD_TERMINAL_PASS` | credentials of the service terminal used for order dispatch |

The defaults in `nuxt.config.ts` point at `http://localhost/apila/graphql`, so a local backend has to be
served on that path or the variable overridden.

## Codegen

The schema is fetched from the running backend at codegen time:

```bash
GRAPHQL_URL=https://safepets.ru/api/graphql npm run codegen
```

`codegen.ts` reads `process.env.GRAPHQL_URL` (fallback `http://localhost/apila/graphql`) and writes to
`gql/`; `graphql.config.yml` is the editor/IDE counterpart. Regenerate and commit whenever a `.graphql`
document or the backend schema changes — components import typed documents such as `AddCartItemDocument`
from `~/gql/graphql`, so a stale `gql/` folder becomes a type error somewhere else.

## Build and run

```bash
npm run build                          # .output/
node .output/server/index.mjs          # or ./start.sh, which exports .env and defaults PORT=3000
```

`npm run generate` produces the static variant; the prerender settings in `nuxt.config.ts` skip
`/login`, `/register` and `/profile`, which are session-bound.

## Deployment, as the repository does it

`deploy.sh` — stop `nuxt-app.service`, `git pull`, `npm run build`, start the unit again.

`deploy.js` — uploads `.output/public` to a Yandex Object Storage bucket (the prerendered assets).
Credentials come from the environment: `YANDEX_S3_ACCESS_KEY`, `YANDEX_S3_SECRET_KEY`,
`YANDEX_S3_BUCKET`, `YANDEX_S3_ENDPOINT`.

## Testing

There is none: no test runner, no spec files, no CI. The correctness that matters most lives in
`utils/text.ts` (line breaking and font fitting) and in `server/utils/svg.server.ts` (the same layout
without a browser) — pure functions over data, and the cheapest place to start with Vitest.

## Known gaps

- No tests, no CI, no ESLint config — only `.prettierrc` (`semi: false`, single quotes, 4 spaces).
- Analytics IDs (GTM, Yandex Metrika, Top.Mail.Ru) are hardcoded in `app.vue`.
- The legacy designer JSON in `data/source/` is carried along; `GET /api/dt-texts-data/:filename`
  exists only to read it.
- `.npmrc` sets `shamefully-hoist=true` and `strict-peer-dependencies=false`; the lockfile is the
  single source of truth for versions.
- `npm audit` on the committed lockfile reports 5 critical, 71 high, 14 moderate advisories. Most sit in
  the build-time toolchain (GraphQL Codegen, `tar`, `simple-git`, `shell-quote`); the ones that touch
  production code are `swiper` (prototype pollution in the carousel) and `@nuxt/devtools` < 3.3.1
  (unauthenticated RPC → command execution on the developer's machine).
